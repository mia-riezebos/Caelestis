feat(userscript): manage published templates from the tree

The panel could upload a template to a server and never see it again. The tree
drew folders only, so a published template had no row, and therefore no rename,
no delete, no way to move it, and no way to tell whether anyone else could even
see it.

Templates now come from the manifest and sit under the folder they belong to,
alongside the nodes and cached with them — a refresh fetches both together, since
a template row is drawn under a folder and updating one without the other puts
rows under folders that no longer exist. Unpublished ones are dimmed and labelled
rather than hidden: an admin can see them, everyone else cannot, and a row that
looked identical either way said nothing about which.

The row's menu carries the verbs a server template actually has — move to another
folder, publish or unpublish, replace the artwork, rename, delete. Renaming is a
rename, not a re-upload, so nothing that caches chunks is told the pixels moved.
Replacing artwork is sourced from a Local template rather than a file picker,
because a raw image has no placement and the origin is half of what a version is.

Deleting says out loud that everyone connected loses it, which is the one delete
in this tree that reaches other people.

Also fixes `uploadTemplate` reading `id` off a response that answers with
`templateId`, so every upload handed back an empty string that callers then
treated as real.

Not in this change: the userscript still never downloads chunks, so a published
template is something you can manage but not yet see on the canvas. That is the
missing half of the product and wants its own PR.
